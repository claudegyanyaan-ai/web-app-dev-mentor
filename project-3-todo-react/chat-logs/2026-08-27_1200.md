## Deployment
1. Committed and pushed - confirmed `.gitignore` (auto-generated by create-next-app)
   correctly excluded `node_modules/` and `.next/` (only 67.60 KiB pushed for 23 files).
2. First Vercel deploy attempt FAILED: `Module not found` on the `import TaskList from
   "../components/TaskList"` line. Root cause: the components folder was accidentally
   created as `Components` (capital C) locally. Windows' filesystem is case-insensitive so
   this worked fine locally and even confused an earlier check where I'd noted the mismatch
   as harmless - but Vercel builds on Linux, which IS case-sensitive, so the import couldn't
   resolve there.
3. Fixed via a two-step `git mv` (Components -> components_temp -> components) - a known
   trick for forcing Git to register a case-only rename on Windows, since a direct rename is
   often silently ignored. Pushed the fix, redeployed - build succeeded.
4. Verified live and confirmed via screenshot: https://web-app-dev-mentor-project-3-to-do.vercel.app/
   Deployed as the third separate Vercel project on the same combined repo, this time with
   an actual `npm run build` step (unlike Projects 1-2's zero-build static hosting).

## Side-question (before Project 4 kickoff)
Learner asked, after the quiz, how the `localhost:3000` dev URL is generated, and specifically
whether there is a line of code in this project that writes it.
Answer given: no — it is not authored in project code at all. It's automatic behavior of the
`next dev` process (run via `npm run dev`), which defaults to `localhost` on port `3000` unless
told otherwise. The only file where this could be customized is `next.config.mjs` (e.g. to force
a different port), but by default nothing there configures it either — it's pure tooling default,
same as `npm install` auto-creating `node_modules` without being told to in code.
