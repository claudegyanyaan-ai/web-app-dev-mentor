## Build sequence
1. Replaced `app/page.js` with a minimal skeleton (centered card, heading, placeholder
   text) - confirmed rendering correctly with Fast Refresh (no manual reload needed).
2. Built `components/TaskItem.js` - first exposure to props (`{ task }` parameter),
   explained as a reusable markup template fed different data each call.
3. Built `components/TaskList.js` - introduced `.map()` to transform an array of tasks into
   `<TaskItem>` elements, and the required `key` prop for React's list-tracking.
4. Wired `TaskList` into `page.js` with hardcoded sample data to prove the render pipeline
   end-to-end before adding real state - confirmed via screenshot (3 sample tasks, one
   struck through).
5. Built `components/AddTaskForm.js` - introduced `useState`, the `"use client"` directive
   (client vs. server components), and the "pass a function down as a prop" pattern
   (`onAddTask`) so the child can trigger a change without owning the data.
6. Wired real `useState`-backed tasks into `page.js`, replacing sample data - confirmed
   Add works live with no reload. Learner correctly predicted that data would NOT survive a
   refresh yet (useState is memory-only, same gap Project 2 had before localStorage) -
   confirmed this is expected, not a bug.
7. Wired toggle (checkbox/click) and delete via props passed down through TaskList to
   TaskItem (`onToggle={() => onToggle(index)}` pattern - React's equivalent of Project 2's
   data-index trick). Hit a debugging detour: Delete button wasn't rendering despite correct
   code in TaskItem.js and TaskList.js. Diagnosed step by step (checked for a stray pasted
   line, checked for duplicate files, checked browser console for errors - none found) and
   resolved by fully restarting the dev server (`Ctrl+C` then `npm run dev` again) - a stale
   Turbopack hot-reload cache was the likely cause. Confirmed working after restart
   (screenshot showing Delete buttons + working toggle).
8. Added persistence via TWO separate `useEffect` hooks in `page.js`: one with `[]` deps
   (load from localStorage once on mount) and one with `[tasks, loaded]` deps (save to
   localStorage whenever tasks change), with a `loaded` flag guarding against the save-effect
   firing with an empty array before the load-effect finishes. Confirmed tasks survive a
   full page refresh.
9. Styling pass in progress: gave updated `TaskItem.js` (checkbox instead of clickable text,
   teal accent via `accent-teal-600`) and `AddTaskForm.js` (teal Add button, focus ring)
   to match the teal branding used in Projects 1-2. Awaiting learner confirmation/screenshot.
