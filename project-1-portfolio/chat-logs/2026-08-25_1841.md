## Bug resolved
- The `styles.css` "nothing changed" issue was traced to `index.html` losing its `<head>`
  section (likely dropped during an earlier edit) — no `<link rel="stylesheet">` meant the
  browser never requested the CSS at all. Learner restored the `<head>` block; styling
  applied correctly afterward (confirmed via screenshot: horizontal nav, styled hero, etc.)
- Lesson: HTML fails silently on structural mistakes (no head, no console error) — DevTools
  Network tab is the reliable way to check whether a linked file (css/js) is actually being
  requested and with what status code.

## Concepts added (mirrored in CONCEPTS.md)
- DOM selection via `document.querySelector()` — same selector syntax as CSS, used to find
  elements from JS.
- Events and `addEventListener()` — JS code that only runs in response to a user action.
- `classList.toggle()` as a one-line on/off switch; JS only flips a class, CSS still owns
  what the class actually looks like (separation of concerns, reinforced from Step 6).
- Media queries only apply below the specified viewport width — nothing visibly changes at
  normal desktop width, which is expected behavior, not a bug (was a source of confusion).
