Build checklist

  • Neon Postgres database created and connected via SQLAlchemy
  • FastAPI backend: models.py (Task table), schemas.py (request/response shapes)
  • Four CRUD endpoints: GET/POST /tasks, PUT/DELETE /tasks/{id} — tested live via Swagger docs
  • CORS configured to allow the frontend to call the backend
  • Next.js frontend scaffolded, lib/api.js wraps all fetch() calls to the backend
  • Components rebuilt to key off task.id (a real database id) instead of array index
  • Edit-task-text feature added — full CRUD demonstrated live in the UI
  • Environment variables used correctly: .env (backend, git-ignored), NEXT_PUBLIC_API_URL (frontend)
  • Deployed as two separate services — backend to Render, frontend to Vercel
  • Verified live end-to-end: adding/editing/toggling/deleting tasks on the real deployed site
Bug fixed — DATABASE_URL not loading: a PowerShell command (Out-File -Encoding utf8) silently added an invisible byte-order-mark to .env, which python-dotenv couldn't parse past. Fixed by editing .env directly in a text editor instead.
Bug fixed — Render Start Command: Render's default placeholder (gunicorn your_application.wsgi) is for Django, not FastAPI. Caught before deploying and corrected to uvicorn main:app --host 0.0.0.0 --port $PORT.
Bug fixed — CORS blocked the deployed frontend: the backend's allow-list only had localhost:3000; the real deployed Vercel URL had to be added before the live frontend could successfully call the live backend.

Concepts introduced

Full plain-English explanations in CONCEPTS.md. Summary:

  • Three-tier architecture — frontend, backend, and database as separate deployed pieces
  • FastAPI + uvicorn — defining endpoints vs. actually running the server
  • CRUD mapped onto REST endpoints (GET/POST/PUT/DELETE)
  • SQLAlchemy — models (table shape), engine (connection), sessions (per-request)
  • Pydantic schemas — API request/response shape, separate from the database model
  • Environment variables and .env — keeping secrets out of code and git
  • CORS — why browsers block cross-origin requests unless explicitly allowed
  • The database as the real source of truth, React state as a local cache of it
  • NEXT_PUBLIC_ prefix — which env vars are safe/needed in browser-side code
  • Deploying two independently configured services that must find each other
