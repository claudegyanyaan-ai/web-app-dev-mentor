Build checklist

  • Role-based access control — `role` column (student/admin) + require_admin() dependency gating all admin endpoints
  • First admin account bootstrapped via direct Neon SQL UPDATE, not self-service signup
  • Admin course/lesson CRUD UI (text + embedded video lessons)
  • Admin quiz builder — dynamic add/remove questions and options, single correct answer per question
  • Separate student-facing (QuizOut, no answers) vs admin-facing (QuizAdminOut, with answers) response schemas to prevent answer leakage
  • Server-side-only quiz grading — never trusts a client-submitted score
  • Enrollment gate on lesson completion — CourseEnrollment required before progress counts, idempotent mark-complete
  • Per-course progress bar (% lessons complete) and quiz attempt history with unlimited retakes
  • PWA packaging reusing Project 6's network-first service worker pattern (not Project 5/7's older cache-first pattern)
  • Deployed as two services — backend to Render, frontend to Vercel, database on Neon — verified live end-to-end

Concepts introduced

Full plain-English explanations in CONCEPTS.md. Summary:

  • Role-based access control via a require_admin() dependency, not just "logged in or not"
  • Hiding quiz answers is a response-schema problem, not a frontend-hides-it problem
  • A missing SQLAlchemy relationship fails silently — it just makes a feature impossible later, not an error now
  • Enrollment as an authorization gate, not just a display record
  • Idempotent writes — marking a lesson complete twice shouldn't double-count it
  • create-next-app --skip-install to avoid baking Linux binaries into a macOS node_modules
  • A PWA service worker's scope is the browser origin, not "this one project" — old ones can hijack new dev servers on the same port
  • Network-first vs. cache-first service worker strategy, and why cache-first enables stale-cache incidents
  • Relative import depth in nested Next.js App Router routes
  • git push ≠ deployed, twice over: local commit → GitHub push → actual Render redeploy
  • CORS allow_origins has to name the real deployed frontend URL, not just localhost

Checkpoint quiz

1. Why does hiding quiz answers from students have to happen via a separate response schema (QuizOut vs QuizAdminOut), rather than just not rendering is_correct in the frontend?
2. The missing Course↔Quiz relationship didn't crash anything when it was absent — so how did it actually surface as a problem?
3. Why does /lessons/{id}/complete check for an existing enrollment before recording a completion, instead of just recording it for any logged-in user?
4. What made the Project 8 admin page render completely unstyled, and why did it take checking the Network tab specifically to find it?
5. Why does a network-first service worker avoid the class of bug that a cache-first one caused here?
6. After pushing the CORS fix to GitHub, the live app still failed the same way for a bit — what was actually still true, and how was it confirmed?
