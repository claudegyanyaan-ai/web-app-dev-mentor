Bug fixed along the way: the first version of "Edit" used the browser's native prompt() dialog, which threw Error: prompt() is not supported inside the embedded VS Code preview (dialogs are disabled there). Rebuilt Edit as an inline input field instead — no native dialog needed.

Concepts introduced

Full plain-English explanations in CONCEPTS.md. Summary:

  • State — the app's data lives in one JS array, the screen just reflects it
  • Render-by-rebuild — wipe and redraw the whole list from the array on every change
  • Event delegation — one listener on the parent list, not one per button
  • data-* attributes — tagging elements with which task they belong to
  • Template literals — building HTML strings with embedded JS values
  • localStorage + JSON.stringify/parse — client-side persistence across refreshes
  • event.preventDefault() — stopping a form's default page-reload on submit
  • Diagnosing an environment limitation vs. an actual code bug (the prompt() case)

Checkpoint quiz

1. Why does the whole task list get wiped and rebuilt every time, instead of just changing the one row that was clicked?
2. What problem does "event delegation" (one listener on the <ul>) actually solve here?
3. What is localStorage actually storing — and why does the data have to go through JSON.stringify/JSON.parse?
4. Why did prompt() fail, and was that a bug in our code?
5. What does data-index="2" on a button actually do, and how does the click handler use it?

Answered verbally in the mentoring session — see debrief.
